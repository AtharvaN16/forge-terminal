Done: the way on

In testing, people stopped on Done and didn’t know how to go on. Today, ↵ (back to home) has a different word in every mode, esc does nothing, and “continue editing →” looks like the next step. The Today screens are captured from the app (dark, 80 × 24); the concepts edit those captures.

Held fixed

The header bar, the strip, the seven-row bar and now/was, as built. Only how you leave Done changes. Tab 2 is the words for ↵. Tab 3 is where the way on sits and how it looks. Any tab-3 concept can take any tab-2 word.

Questions for you

  1. New strings to approve: home, next file, done (Y1–Y3), ← home (Y4), Next file (Y8, Y10), search or enter a file path… (Y9: home's placeholder without “OR”).
  2. Should esc on Done go home in every concept? Today it does nothing. I'd make it go home whichever concept wins.
  3. Should dropping or pasting a file on Done start the next one straight away, even where there is no drop zone? It would skip the trip home.
  4. Should “continue editing →” be louder, quieter or renamed once ↵ is clear? Only Y8 and Y10 touch it.
