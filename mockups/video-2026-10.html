Video and sound

Forge gets an ffmpeg engine: video and sound go through the same convert, compress and enhance flows as images, plus a trim screen built for the terminal. The case it’s built around: a 184 MB screen recording that has to go into Slack, a GitHub comment or Discord, with the dead first seconds cut off. Home, Method, Target size and Save as are captured from the app at 80 × 24; everything else is drawn with the app’s own art functions.

RULES · what it does with awkward files

  1. Probed by content. Box signatures (ftyp, EBML, RIFF, OggS, fLaC, ID3, FORM) say “video” or “sound” without ffmpeg; ffprobe then gives streams, length, size and rotation. An animated GIF can also be read as a video, so GIF → MP4 shows up in Convert (often 20× smaller).
  2. Copy when nothing needs re-encoding. H.264 in MOV → MP4, mute, trim and keeping only the sound (AAC → M4A) copy the streams: seconds, lossless. Anything that changes the picture or sound re-encodes.
  3. Streams, never buffers. Images are read into memory; a 40 GB ProRes file can’t be. ffmpeg reads the source and writes a temp file beside the output, then it is renamed (invariant 6). Free space is checked first.
  4. Rotation. Phones store rotation as a tag; dimensions are reported as you see them, and the output is upright.
  5. Odd sizes. H.264 needs even width and height: sizes are rounded to even, never padded with a black line.
  6. Variable frame rate. Screen recordings change frame rate as the screen changes; it is kept, not averaged (Clop learnt this: averaging turned 60 fps recordings into 23 fps).
  7. HDR. iPhone video is HDR (HLG or Dolby Vision). HEVC keeps it. H.264, WebM and GIF can’t carry it, so it is tone-mapped to normal range. Clop and compressO skip this and their output looks washed out.
  8. Several sound tracks, subtitles, chapters. Kept where the target can carry them; bitmap subtitles are dropped with a warning. Sound only → the first track.
  9. Metadata. Stripped by default, as for images (iPhone videos carry the GPS position). Creation date and rotation are kept. --keep-metadata keeps it all.
  10. Grew instead of shrank. Shown in orange as Done does now. For compress, if the result is bigger than the source, Done says so and the original is the better file (nothing is replaced, ever).
  11. Protected files (iTunes FairPlay), damaged or cut-short files: the error panel (E5), in plain words.
  12. No sound / no picture. Mute and loudness are missing for a silent video; video targets are missing for a sound file.
  13. Several files. One at a time (the hardware encoder is the limit), “2 of 5” above the bar. Trim and Save a frame are offered for one file only.
  14. Long jobs. The Mac is kept awake while it encodes (caffeinate), and only then.
  15. Encoders. Convert uses Apple’s hardware encoder (fast); compress uses x264 (smaller at the same quality, which is the point of compress). Windows uses x264 throughout.
  16. Getting ffmpeg. A Homebrew ffmpeg with the needed encoders is used if it is there. Otherwise a Forge extension, “video”, about 31 MB (my estimate, to measure), offered in place like Boost. Built for this: only the codecs Forge uses, so it is half compressO’s 124 MB.

BEYOND CLOP · where this ends up better than Clop and compressO

  1. Copy, don’t re-encode, when possible. Clop always re-encodes an MP4. A MOV → MP4 that is already H.264 is a few seconds here and loses nothing.
  2. Trim, with the frames and the sound. Clop has no trim at all; compressO has one but no waveform. Finding the silence before you speak is the most common trim.
  3. Honest size target. Two-pass, so 10 MB is under 10 MB. Clop does one pass and retries once if it misses. When the picture had to shrink, Done says so; when the size is out of reach, you are told before the encode, not after.
  4. HDR that doesn’t wash out. Neither Clop nor compressO handle it.
  5. The bar is speed-aware. compressO’s bar stalls at 50% on a 2× speed-up because it divides by the source’s length. Ours divides by the output’s.
  6. Measured format offer. After a GIF, the WebP size is measured, not guessed. GIFs dropped in can go to MP4.
  7. Loudness that lands. Clop measures once (its code calls it two-pass but it is one); two passes land on −16 exactly.
  8. Sound gets a real quality screen with the size before encoding, since for sound it is arithmetic.
  9. Save a frame as a picture, at full size.
  10. Smaller download. Clop ships 66 MB of tools; compressO 124 MB of ffmpeg. Ours is only what it needs, or nothing if you have Homebrew’s.
  11. Agents. The same flags in the MCP server, with progress events, so an agent can say “make this under 10 MB” and get a true result back.
