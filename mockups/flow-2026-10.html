Your two questions

Would the smaller logo look nice, and could it break?

It's very unlikely to break: it uses exactly the same characters as today's logo, just fewer of them.

  • Same characters as today. The 4-line version (A below) is the bottom half of today's logo, unchanged. If those characters displayed badly on someone's Mac, today's logo would already be broken.
  • Safer in small windows. Today's logo needs 55 columns, and below that the app hides it entirely. The 4-line version is 11 columns wide, so it fits in any realistic window.
  • One known weak spot, shared with today. If someone increases line spacing in their terminal's settings, block characters show thin gaps between rows. That affects today's logo the same way.
  • What I didn't check: I compared these in a browser using the same font, not inside Terminal.app. Before building it, the mark should be printed in Terminal.app, iTerm2 and Ghostty to compare. It's a 10-minute check.

Before converting, can we actually know what the size will be?

Exactly? Only by doing the conversion. The proposal does exactly that, quietly, as soon as you drop the file.

No formula predicts a JPEG or WebP size precisely, because it depends on what's in the picture. So the idea isn't to predict the size. The app makes the file in the background with the filled-in choices, keeps it aside, and shows its real size. If you press ↵ it saves that file, so nothing is converted twice. If you change a choice, it makes the file again. If you leave, the file is thrown away. This fits how the app already writes files: it saves to a temporary file and then moves it into place.

How long that takes, measured on this Mac with the same image library the app uses:

FileJPEGWebPAVIF
test.png (2756×774, 122 KB)0.02 s0.09 s0.4 s
12-megapixel photo-sized test images*0.05–0.09 s0.5–1.2 s0.7–3.6 s

* Three generated test images (smooth, detailed and noisy), not real photos. Real iPhone photos should be checked before relying on these numbers.

Most of the time the size appears before you've finished reading the line. For AVIF on a big photo it takes a few seconds, and the line shows "checking the size…" until it's ready. It never shows a made-up number.

The other formats in the list (the "about 39 KB" in section 2) are a different matter. Making the file in every format would be too slow, mostly because of AVIF, so those are estimates. I tested two ways of estimating:

MethodHow far off it wasVerdict
Shrink the image, convert it, scale the size up46–71% too smallToo wrong to use
Convert 9 small full-detail pieces of the image, scale up1–18% off; once 99% on a very small fileGood enough for "about", in a fraction of the time

A decision for you: show "about" estimates in the list (helpful, sometimes off), or show only the exact size of the format you've picked (always true, less to compare)? I lean towards estimates, always labelled "about", and replaced by the exact number once you pick one. Two limits either way: very large files (say, over 50 MB) would skip the background step and show the size after converting, and for PDF and Word conversions the first version would show sizes afterwards only.
