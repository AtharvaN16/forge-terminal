Redesigning the terminal UI

A survey of the best terminal interfaces as of October 2026, six deliberately different directions for forge, then one of them developed down to individual frames. Mockups only. No code has been changed.

What the frames show

  1. 1The mark takes 9 of 40 rows (22%) on every launch, and then stays in scrollback. The hammer is charming once. By the hundredth launch it is in the way.
  2. 2"Mode" is a state the user has to track. The line restates it, and it has three colour pairs of its own. The verb could be part of the request instead of a global setting.
  3. 3Five sequential questions for one conversion: format → quality → destination → name → run. Every one needs its own ↵, and answered questions disappear (audit #14).
  4. 4Three of six hints say "likely smaller". The picker guesses even though the app could measure (audit #30).
  5. 5The result never says where the file went (audit #9). It spends 4 rows on two boxed filenames and 0 on the path.
  6. ·Colour carries too many meanings: 18 palette tokens, including 3 mode fg/bg pairs. The amber accent, cyan tag, violet label and mode colour all compete in the same frame.

What to keep. The foundations are right, and several were measured to get there: one persistent screen with history above the prompt, files probed by content, every target derived from targetsFor(), symbols paired with words so the UI survives NO_COLOR, honest indeterminate progress, and paste-to-attach. The redesign changes the surface, not those invariants.

01The market, October 2026

The terminal interfaces most often cited as the best-made, and the move each is admired for. First what changed in the last year, then the apps grouped by layout model, because layout is the first decision this redesign has to make.

What changed in 2025–26

Agent CLIs became full-screen, and kept a way out

Claude Code first rebuilt its Ink renderer to redraw only changed cells (Dec 2025). It then added an opt-in full-screen mode with a pinned prompt and click-to-expand tool output, which became the default for users who started after May 2026. [ writes the transcript back into your real scrollback. Gemini CLI v0.15 and Amp made similar moves; Amp built its own renderer and Gemini keeps history after exit.

↳ never trap the user's work in the full-screen buffer

Renderers that never flicker

Charm v2 shipped in Feb 2026 (Bubble Tea, Lip Gloss, Bubbles), with a renderer that only redraws changed cells, synchronized output, inline images and light/dark detection. opencode moved to OpenTUI (a Zig core with React bindings). Toad advertises updates as small as one character. Flicker now reads as a defect.

↳ relevant: audit #5, frames left behind after a resize

The terminal draws progress itself

Ghostty 1.2 (Sept 2025) and iTerm2 3.6.6+ render OSC 9;4 as a native progress bar in the tab and title bar. It has an indeterminate state, so a single-file conversion can show native activity without inventing a percentage, which fits invariant 7 exactly.

↳ adopted below, for free

Terminal.app caught up partly

macOS Tahoe's Terminal.app gained 24-bit colour and Powerline glyphs. There is still no reported image protocol (inferred: no coverage mentions one). The baseline for Forge is therefore truecolour, no images and no Nerd Font.

↳ images must be progressive enhancement

Inline transcript: draws in scrollback

Claude Code

Prompt at the bottom with history above it. A spinner with rotating verbs and a per-character shimmer that stops when idle. Tool output collapses to one line; / and @ open menus.

↳ shimmer only while working

Gum / Huh

One widget at a time (choose, filter, spin, input), each leaving one tidy line behind. Inline, with no screen takeover.

↳ an answer collapses to a single line

Warp blocks · Toad

Each command or turn is a typed block you can select, copy and refer to. Textual's inline=True mode renders under the shell prompt and leaves cleanly on exit.

↳ one turn = one addressable block

Full-screen workbench

yazi

Three columns (Miller layout) with async previews. Chooses kitty, iTerm2 or Sixel itself and falls back to Chafa character art.

↳ capability detection with a fallback chain

lazygit · k9s

Panels that never move, a footer that shows the keys for the current context, ? for every key. k9s adds a :resource command bar and breadcrumbs.

↳ stable layout, keys shown progressively

btop · posting

btop uses braille graphs and gradient meters whose colour maps to value. posting (Textual) has "jump mode", where letter labels let you focus any widget, plus a command palette.

↳ colour encodes magnitude, not decoration

Palettes, pickers and themes

fzf · television · atuin

A fuzzy filter is the whole interface. television adds pluggable "channels" (data sources) and a preview pane.

↳ type intent, not structure

Crush · opencode

Crush has Charm's pastel truecolour personality. opencode's "system" theme adapts to the terminal background, and each colour has separate light and dark values.

↳ adapt to the user's terminal

Codex CLI

Full-screen Ratatui, restrained greyscale with one accent and diffs as the loud colour. Status lines follow the theme.

↳ colour reserved for what changed

02What the best ones share

Nine principles from the survey. Each one is used below to judge the directions.

1 · One accent, greyscale for the rest

Codex, Claude Code and Crush each have one brand colour, with structure carried by brightness. Semantic colour (ok, fail) appears only on the outcome.

2 · Borders only where there is a boundary

Rounded borders mark something the user can type into or a pane. Content gets whitespace and indentation, not boxes.

3 · Answers stay visible

An answered question collapses to one line and stays in the transcript, so the scrollback is a record, not a pile of dead pickers.

4 · Show the real thing

Measured sizes rather than "likely smaller". Real pixels where the terminal can draw them (kitty graphics, iTerm2, Sixel), with a graceful fallback.

5 · Teach the scriptable form

lazygit's command log and atuin's history show the command behind a UI action, so the TUI also teaches the CLI.

6 · Motion means work is happening

A shimmer or spinner appears only while something is actually running, and stops the instant it finishes. No intros that cannot be skipped.

7 · Defaults you can accept in one key

The best flows pre-fill a sensible answer and let ↵ accept all of it. You only have to get involved when you want something different.

8 · Never flicker, never trap

Redraw only what changed, inside synchronized output. Whatever the layout, the user's results must end up in their real scrollback.

9 · Scale down gracefully

Narrow widths, light themes, NO_COLOR and terminals without image support each get a deliberate layout, not a broken one.

03Go broad: six directions

Each direction shows the same task: convert an iPhone photo, IMG_4127.HEIC (2.4 MB), to WebP and save it to the Desktop. They differ in layout model, input model and attitude, not in palette. All six use the proposed Ember palette so they can be compared fairly.

ATranscript

Today's model done properly. Questions still come one at a time, but each answer collapses to one line and stays. The banner shrinks to a 5-column mark, and receipts include the path.

Good
  • Smallest change from today
  • Scrollback becomes a real session log
  • Fits Ink's <Static> model exactly
Weak
  • Still about 4 keystrokes per conversion
  • Sequential: you cannot see the whole plan before committing
Claude CodeCodex CLIHuh

BSentence

The whole request is one editable sentence. The defaults are already filled in, so ↵ converts immediately, or Tab moves between the slots to change them. Underneath it, the equivalent CLI command updates as you edit.

Good
  • One keystroke for the default case
  • See the whole plan before running
  • Teaches the CLI for free
  • Slots come from targetsFor(), so nothing is hardcoded
Weak
  • Slot editing is a new idiom to learn
  • Long sentences need a narrow-width layout
lazygit command logatuinRaycast arguments

CWorkbench

A full-screen, three-pane file manager built around conversion: browse on the left, a live image preview in the middle, the output plan on the right. You pick files from a folder instead of dropping them in.

Good
  • Best for working through a folder
  • Everything is visible at once
  • Most impressive in a screenshot
Weak
  • Gives up the transcript, so the session leaves no record
  • Conflicts with drag-and-drop, the product's core gesture
  • Ink is weak at alt-screen pane layout; this is really Ratatui or Bubble Tea territory
yazisuperfilelazygitharlequin

DPalette

Intent first. Drop a file and type what you want ("web small", "under 2mb", "pages 3-5"). A fuzzy-ranked list of actions is derived from the file's capabilities, with your recent recipes listed first.

Good
  • Fastest for experts, with no menus to read
  • Scales to many actions as engines grow
  • Recipes give repeat use a single keystroke
Weak
  • A blank box is hard for beginners to discover
  • The ranking needs tuning, and a phrase-to-action vocabulary is a soft form of natural language, which the spec rules out
fzftelevisionRaycastWarp

EDarkroom

Preview first. Before and after appear side by side as real pixels (over the kitty or iTerm2 image protocols), at a 1:1 crop so compression artifacts are visible. The slider re-encodes as you move it, so the size shown is the real size.

Good
  • Answers the real question: "is this quality acceptable?"
  • Makes compression trustworthy
  • Visually distinctive
Weak
  • Needs Ghostty, kitty, iTerm2 or WezTerm. Terminal.app (truecolour since Tahoe, but no image protocol) falls back to coarse ▀ half-blocks
  • Too heavy as the default for every conversion
yazi previewsGhosttychafaSquoosh (web)

FDispatch

Batches first. Drop a folder or forty files and get a live table: real per-file results, a bar driven by files finished (not invented), failures shown in place, and a running total.

Good
  • Fixes the weakest part of today's UI: multi-file (audit #6, #7, #16)
  • Every number shown is real
  • Looks like btop or k9s, which gives power users confidence
Weak
  • A layout only for batches, not a whole UI
  • Overkill for one file

07Design system

  
The changes are mostly removals: three mode colour pairs, the tag colour and the label violet all go.


  
Colour: from 18 tokens to 8, plus a selection fill

Contrast figures are approximate against #15161b and should be re-measured the way theme.ts already documents its values. The ember is the hot-metal colour of the existing mark, kept as the only accent so focus is never ambiguous. A conversion that grew uses warn plus a "+" sign, which removes the need for a separate larger orange.


  

    

      
Glyphs

      

        ● staged   ◐ working   ✓ done   ✕ failed   ⚠ heads-up

        ▾ slot   ❯ option cursor   › prompt   → transform

        ✧ offer (kept from today)
      

      
No Nerd Font glyphs: Terminal.app users do not have them, and the current symbol set already survives every font.

    

    

      
Layout rules

      
Two-space indent under a subject line. One blank line between blocks. A border only around the input and popovers. A rule (┄) only to separate the live region from the transcript. Right-aligned numbers so sizes line up across receipts.

    

    

      
Motion

      
Three animations in total: the ember shimmer on the working verb, the ◐ spinner, and the hammer, which plays once ever. Each stops the frame its work stops. All are off under NO_COLOR or FORGE_REDUCED_MOTION.

    

    

      
Keys

      
↵ accept everything · tab next slot · ↑↓ change the focused slot (on an empty prompt, history) · p preview · c copy as command · o/r open/reveal last · esc clear then back (as today) · / commands · ? all keys.

    

  







  
08What it costs

  
A rough mapping onto the current code. None of it touches core/ or engines/ beyond one new data function.

  

    
PieceChangeSize

    
      
Sentence composerNew Sentence component that replaces the sequential Select → Slider → destination → name steps in App.tsx. A slot is {label, value, options} built from targetsFor() and the action option schemas, which already exist.L

      
Speculative encodeWhen the slots settle (debounced), encode for real into the atomic temp file. ↵ then only has to rename, so the size shown is the result. Fits invariant 6 directly. Needs cancellation, and a cap on input size so a 200 MB TIFF does not encode in the background.M

      
ReceiptsRewrite the result block in blocks.tsx: path first, OSC 8 link (hyperlink.ts exists), elapsed time, equivalent command.S

      
Equivalent commandA pure intentToArgv() in cli/, the inverse of args.ts. Unit-testable as a round trip, which also catches CLI/shell drift like audit #2.S

      
Batch tableExtend Progress.tsx with per-file rows from the existing run events. The bar is driven by completed jobs.M

      
Image protocolDetect kitty / iTerm2 support (an XTGETTCAP or kitty graphics query, plus TERM_PROGRAM). Write images outside Ink's diff, the same way intro.ts already writes outside Ink. This is the riskiest piece: it is hard to reconcile with Ink's redraws, so prototype it first.L · risk

      
Native progressEmit OSC 9;4 from the shell layer: state 3 (indeterminate) for a single file, a real percentage of completed jobs for a batch, cleared on finish. Terminals that do not support it ignore it.XS

      
Palette & bannerCollapse theme.ts to 8 tokens and add a compact 2-row mark. First-run-only intro behind a preference flag.S

    
  


  
Suggested order

  
1. Palette, compact banner, receipts: cheap, visible, and they fix audit #9, #26, #27 on their own. 2. Sentence composer plus equivalent command: the core of the redesign. 3. Speculative encode, to turn "likely smaller" into real numbers. 4. Batch table. 5. Image previews, starting with a throwaway spike to prove Ink can coexist with the kitty protocol.
