Clipboard

Copy an image, let Forge work on it, paste the result. The clipboard becomes a source and a destination, like a file and a folder. Screens are the real app at 80 × 24, edited where the clipboard changes them.

Decided ⌘V chip in the field, and for every field hint (grey in colour mode) · no error for text · never bigger · E3 wordingOpen 8 questionsRound 4

In plain words

  1. You copy a picture, like a screenshot or an image from a web page.
  2. You open Forge. The field says ⌘V to paste from clipboard; ⌘V brings the picture in, as if you had dropped a file.
  3. You pick what to do (shrink it, convert it, remove the background) with the same steps as a file.
  4. Forge puts the result back on the clipboard. There is no file to name or save.
  5. You paste wherever you were going. Not happy? Press u and the original comes back.
  6. From the command line, forge clip does all of it in one go.

Questions for you

  1. Keep /clip as well (B), or is ⌘V enough?
  2. A result that would be larger: ↵ switched off at those quality levels (my pick), or ↵ allowed, and Forge just leaves the clipboard alone?
  3. No Save as for a copied image (Step 6)? The result goes straight back on the clipboard; s saves a file if you want one.
  4. Lossy PNG first. Screenshots are PNGs and Forge cannot shrink a PNG today. Build lossy PNG before this (my pick), or have clipboard compress turn PNGs into JPEG? JPEG loses transparency and blurs text.
  5. The name it pastes with (Step 7): Copied image.png, Screenshot 2026-10-16 at 12.40.png, or image.png?
  6. Retina → 1× as a compress option (halves each side, about ¼ the size), or leave it to Resize in enhance?
  7. Windows in the first version, or later? There the key would be ctrl-v.
  8. Words drawn in the screens, to approve: “Copied image” · “On the clipboard” · “undo” · “save a copy”. In E3, “uploaded” could be “copied”, since nothing is uploaded; kept as you wrote it.

SCREENSKey hints inside a field

Decided: one look for every key hint in a text field, starting with ⌘V. The ⌘V hint shows only while the clipboard holds a picture; Forge checks when it opens and whenever you come back to its window. B is a separate yes or no.

SCREENWhat goes back on the clipboard

Two things at once, because different apps read different ones. Which apps read which is a guess until it is tested.

1 · The picture

PNG data, 1.2 MB. What Chrome, Safari, Figma, Notes and Slack in a browser read when you paste.

2 · The file

A reference to Copied image.png in Forge's cache folder. What the Slack app, Mail, Messages and Finder take when you paste: the exact compressed bytes.

Kept aside

The original 4.1 MB image, so u (or forge clip --undo) can put it back. Only the last one is kept.

SCREENWhen the clipboard changes meanwhile

Text on the clipboard is not a case: then the hint simply is not shown. A result that would be larger has no screen either (see the table below).

RULESOther cases, no new screen needed

A result that would be largerRare, but compress can do it: a JPEG saved at 60 asked for at 80, or a PNG another tool has already squeezed. The quality step shows it live, in orange, as the slider moves, so you know before ↵. At those levels ↵ is off, so a larger image is never put back and there is no screen for it.
Files copied in Finder (⌘C)Treated exactly like files dropped on home, Save as included, because they have a real folder. The new files then go on the clipboard, so ⌘V pastes the results. Finder also puts each file’s icon on the clipboard as a picture; Forge must take the file, never the icon.
Several files copiedThe several-files list, as a multi-file drop.
Window screenshot with a shadow, converted to JPEGTransparency flattened, as today.
Colours and sharpnessThe colour profile (screenshots are Display P3) and the Retina size tag are kept, so it pastes at the right size in the right colours.
A photo copied from PhotosLocation and camera data are stripped.
A copied GIF from a browserThe clipboard only holds its first frame. Forge says so rather than handing back a still.
A PDF copied from PreviewNot in the first version; the picture version of it is used.
Over SSH, or no clipboardNo hint. forge clip says why, as it does with text on the clipboard.

IDEASBetter than Clop

Where this can beat it. None of these are drawn yet; say which to keep.

You see it before it happensClop optimises silently. Forge shows the size live on the quality step, then the before and after on Done.
Every mode, not just smallerRemove the background from a copied image and paste it into Keynote. Boost a small one. Crop it to a circle for an avatar. Convert a copied WebP or HEIC. Get the palette of a copied screenshot.
“Fit for where it’s going”Presets like --for slack, --for github, --for claude, each with that place’s size limit and the size it shrinks images to anyway. Anything bigger is pixels the other side throws away, so shrinking to it costs nothing you would see. (Each limit needs looking up first.)
One-key undou on Done, --undo on the command line. Clop keeps backups in a folder; this is quicker.
Free for agentsClop charges for its MCP server; Forge’s clip tool would be free.
Never worse, never in your wayNever puts back a bigger image, never overwrites a newer copy, strips location data from copied photos.
