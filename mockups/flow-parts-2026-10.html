01Key hints: decided

You chose F1. It's shown here on the three screens with different main keys, as the reference for building it.

The rule that comes with it. Main keys are what this screen is for, drawn as caps two spaces apart. The footnote is everything that's always available (esc, ctrl-n new, ctrl-c quit), drawn as dim text at the right edge. When there isn't room, the footnote drops items from its right end; the main keys never shrink, and the row never wraps.

02Home, in eight directions

The whole first screen, redrawn eight ways. Each one is a complete visual language on its own: logo, mode, where files go, the drop zone and the keys all follow it. No mixing with today's screen. The drop zone is explored separately in the next tab, so judge these on the overall feel.

03The drop zone, on its own

Only the drop zone, out of any screen, so the idea is the only thing you're looking at. Each is shown empty and while typing a path. Whichever you like can sit inside whichever home direction you like.

Real terminal frames. Every frame is ANSI written into xterm.js at 80 columns, drawn as a terminal draws it. The typing frames show path completion (Tab finishes a folder name), which is new and optional.

04The / command list

What appears when you type /. Today it's a plain list of five commands above the prompt.

05Working

The moment between pressing ↵ and the receipt. For a big photo or an AVIF this lasts several seconds. Today it's one dim word. A single file has no percentage (invariant 7), so every option shows activity, not progress. The animations below are live.

06Naming the file

Today it's an empty filled box with the name in its middle row and the full path under it.

07Errors

Captured by saving into a folder without write permission. Today a red card states the problem and the app returns to the empty prompt. The file is unstaged, so to try another folder you start again.
