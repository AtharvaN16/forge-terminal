Yes: BiRefNet-lite fits. Rebuilt to work at 512 pixels, it is 54 MB, peaks at 1.3 GB (down from 13 GB), takes 0.6 s a photo, and agrees with Apple's cut-outs more than any model so far. The memory was never the model itself. The first file turned every "bendy" filter into giant lookup tables. Rebuilt from the original weights, ONNX Runtime does that step directly.

What this shows

  • 512 is as good as 1024 here. Cut-outs are enlarged to the full photo and edges look the same, even zoomed in on fur, the hat weave and the wine splash. Sharpening them first made it worse (a faint glow around edges), so I dropped it.
  • 512 beats 768 on the night photo. 512 finds nothing, which is right. 768 cuts out a stray dark blob. With 512, "top score under 50%" cleanly means "no subject", as Apple says.
  • Compressing barely changes the answers. Storing the bendy-filter weights in half the space moved the mask by under 0.01% on average (at most 3% on any one pixel).
  • The table packing from round 1 didn't double memory. Loading it takes 12 MB more than the unpacked file (219 vs 207 MB). It no longer matters: the new file doesn't need it.

Not proven yet

  • Only 7 photos, and only one with no subject. Worth 20 or more other photos before shipping.
  • All timings are this Mac's processor. A Windows or Linux laptop will be slower, and I couldn't test one.
  • It only ran on ONNX Runtime 1.31.0. Older versions may lack the built-in "bendy filter" step, so the extension must ship 1.31 or newer. I didn't check which version added it.
  • 54 MB is a little over your 50 MB ideal. The remaining weight is the compressed layers (39 MB) and the bendy-filter weights (10 MB), which can't be compressed further this way.
  • I did not try 1024 with the new build. Its export needs over 5.5 GB, past the stop line, and by size it would peak near 3.8 GB, over your 3 GB goal.

Rebuild it exactly

Scripts are in mockups/remove-bg-models-2026-10-round2-build/ (build.sh, export_birefnet.py, shrink.py, requirements.lock.txt). Run ./build.sh <empty folder> 512 with Python 3.12 and git. It downloads about 0.7 GB, takes a few minutes, and peaks near 2 GB. I ran it from scratch in a new folder: both files came out byte-for-byte identical to the ones tested here.
