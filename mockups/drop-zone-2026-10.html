DThe drop zone, once a file lands

Today, dropping a file pastes its path into the field and the zone only dims, as it does for any typing. Nothing says the file was recognised until ↵, and by then home is gone. Here the zone answers the drop: the file goes into it and the field is free again.

What changes in the app. A terminal cannot see a drag or turn one away; the first thing the app learns is the pasted paths. So the app reads the files when the paste arrives, not on ↵. ↵ goes on with them, another drop before ↵ adds to them, esc empties the zone. Several images now convert together: batch conversion moves into the app (the engine and the command line already do it), so a drop of photos is never refused. Format, Quality, Name, Working and Done each get a several-file version later.

A file left out, in red

The app has two colours for trouble: gold warn with ⚠ for "worth a second look" (today's "⚠ 1 skipped"), and red fail with ✕ for errors, drawn as a card with a red frame. A file that could not be read is a failure for that file, so both of these use fail. Both sit under the field, outside the drop zone.
