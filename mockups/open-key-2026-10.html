04Dropping a file on home — what's going on, and the change

Why this is odd: a terminal cannot see a drag. When you drop a file on it, all that happens is the terminal pastes the file's path as text, exactly as if you'd pressed ⌘V. Forge guesses "that was a drop" and answers with the drop-zone card. Today it only makes that guess if the text field is empty. If there is already anything in the field (even one letter), the pasted path is treated as typing: it goes into the field, the zone just dims, and no card appears. Proposal: if the pasted text is a real file or folder on disk, it is a drop whatever the field holds: the card plays, the file is staged, the field is cleared. If it's not a real path (plain text, half a path), it stays in the field as typed, as now.

sketches:

One trade-off: pasting a real file's path to edit it (e.g. paste then change the filename) will now stage that file instead. Pasting anything that isn't a real path still edits the field.
