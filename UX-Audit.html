Six root causes

The thirty findings are not thirty unrelated bugs. They cluster into six underlying causes, and fixing a cause tends to close several findings at once. Start here rather than at the top of the list.

CAUSE 01

Copy in core/ is written for one surface

ForgeError carries a single hint string, but it is read by two front ends with different vocabularies. So the CLI is told to type slash-commands it does not have, the shell is told to pass --debug it does not have, and a folder drop is answered with advice to use a folder.

#3#4#11#23
CAUSE 02

The interface offers what it cannot do

A multi-file drop is probed and drawn in full before it is refused. /pdf armed before a file is staged sets the mode line and then swallows Enter. -o is accepted when compressing and quietly dropped. In each case the affordance appears first and the refusal second.

#2#6#7#15
CAUSE 03

Declared defaults are not the effective ones

OptionSpec.default is dead for every select in the shell — Select initialises to firstEnabled(items) and no call site passes an index. Today it only bites on dpi, the one spec whose default is not first. Alongside it: two flags that accept values nothing ever checks.

#8#20#22
CAUSE 04

"Where did my file go?" has no answer

The shell writes to Desktop, the CLI writes beside the source, and the single-file result screen names neither. Two runs into wildly different directories print byte-identical success lines. The batch report already does this correctly.

#9#16#23
CAUSE 05

Rendering assumes a terminal that stays still

A resize draws the new frame correctly and never erases the old one, so orphans accumulate. The mouse handshake fires without consulting mouseSupported(). And one component carries focus in colour alone, which the project's own §13 forbids.

#5#10#24
CAUSE 06

The hint bar is the only teacher, and it is unreliable

There is no menu bar and no man page in view — the hint bar is where every key is learned. It advertises keys that do not apply in the current state, omits ones that do, and no command exists for the single most common intent: leaving.

#12#13#19#21#28

priority surface showing all 30
01

Every invocation prints a Node warning to stderr — including --version

P0both surfacestrust · scripting
$ forge --version
0.1.0
(node:95249) ExperimentalWarning: localStorage is not available because --localstorage-file was not provided.
(Use `node --trace-warnings ...` to show where the warning was created)

Node 26 prints this the moment docx is imported, and engines/registry.ts imports word.ts eagerly at startup — so it fires for --version and --formats, which touch no engine at all. --trace-warnings puts it at node_modules/docx/dist/index.mjs:4337.

Three separate costs. Every scripted use of forge gets noise on stderr. It is the first thing on screen when the shell launches, printed above the banner — the app looks broken before it has drawn a single frame. And the project's own suite is red on it right now.

Fix: lazy-load docx behind the Word engine's run(). That also takes it off the ~270 ms cold start, which is half of finding 27.

src/engines/registry.ts → src/engines/word.ts · test tests/index.test.ts:84

02

-o/--output is silently ignored when compressing — and the error tells you to use it

P1CLIsilent no-op
$ forge noisy.jpg --quality 40 -o elsewhere/
✓ noisy.jpg → noisy-small.jpg
$ ls elsewhere/          # empty — written beside the source instead

CompressIntent in src/cli/args.ts has fields for quality, maxBytes and dpi — but none for output. The flag parses cleanly and is then dropped on the floor.

The second run closes the loop. The collision error says "Pass --force to replace it, or choose a different --output" — offering an escape hatch that does nothing on this path. A user following that advice will conclude the tool is broken, and they will be right.

Fix: honour -o, or refuse it explicitly the way --separate and page-op --output are already refused. Silently swallowing a typed flag is exactly the defect the page-op branch was written to avoid.

03

CLI errors tell you to type shell slash-commands

P1CLIcross-surface copy leak
$ forge noisy.jpg --max-size 1kb --force
✕ Cannot get that small

  noisy.jpg is 11.6 KB even at the lowest quality, which is still over 1 KB.

  Try a larger target, or /convert to a smaller format.   ← no such thing here

Four hint strings in src/core/errors.ts name shell commands: lines 181 (/pdf and /convert), 193, 201 and 236.

The hints are correct in the shell — the shell even auto-falls-back to the convert picker after Nothing to compress. So this is not bad copy, it is right copy on the wrong surface. Finding 4 is the same bug pointing the other way.

Fix: a surface-aware hint, or two hint fields on ForgeError. The error object is shared; the vocabulary cannot be.

04

A read-only destination reports "Conversion failed", not "permission denied"

P1both surfaceserror classification
$ chmod 500 locked && forge big.png --to jpeg -o locked/
✕ Conversion failed

  big.png could not be converted.

  Run again with --debug for the underlying error.

$ … and with --debug:
  system error: Permission denied   ← this was known all along

There is already a permission-denied code, and §11 of the design notes that Node reports EACCES reliably. But only input paths are pre-checked with fs.access. Output paths are not, so an EACCES on write falls through to the generic branch.

Two compounding problems. A precise, fixable diagnosis is thrown away in favour of one that tells the user nothing. And the shell prints the same sentence — telling an interactive user to re-run with --debug, a flag their surface does not have. That is finding 3 in mirror image.

Fix: classify EACCES on write into the existing permission-denied code, and pre-check the destination the way inputs are pre-checked.

05

Resizing the terminal leaves the old frame on screen, and it accumulates

P1shellrendering
$ tmux capture-pane -p | grep -c "current mode"
5            ← after four resizes. One orphan each.

Mid-flow it is worse than duplication — the previous 50-column file card is left hard-wrapped and interleaved with the new one: 

╭─ PNG ─────────────────────────────────────────
───╮
│ a-really-quite-extraordi…y-use-but-people-do.p
 current mode: convert  use / to change mode

 convert  / to change

§13 says width changes are observed via resize on Ink's useStdout() stream, and the new frame is correct at every band — the banding work is good. What is missing is erasing the old one. Anyone who splits a pane mid-conversion sees a screen that looks corrupt.

Fix: clear the previously-rendered region on resize before drawing the new frame.

06

Multi-file drop is a false affordance

P1shelldead end

Drop two files. Both are probed, and a rich card is drawn — per-file format, dimensions, count, total size:

╭─ MIXED ×2 ───────────────────────────────────╮
│ JPEG photo.jpg                          1200×800 │
│ PNG  big.png                           3000×2000 │
│                                                  │
│ 2 files · 86.6 KB                                │
╰──────────────────────────────────────────────────╯

… and only after Enter:

⚠ Converting several files at once isn't supported yet. Drop a single file,
  or esc to clear the list.

The interface builds the expectation, spends the probe cost on both files, and then refuses — at the last possible moment, after the user has committed. There is also no way to remove one file: it is the whole list or nothing. Note this makes spec §10 stale ("one path per drop… splitPastedPaths is deliberately not wired in") — splitting is wired in now.

Fix: say it in the card at staging time, or do not stage the second file at all. Refusing at Enter is the one place it cannot go.

07

A failed conversion leaves the file staged, and the next drop appends

P1shellflow trap
✕ Conversion failed  (big.png)

 current mode: convert  big.png          ← still staged

› photo.jpg  ⏎

╭─ MIXED ×2 ───╮ … ⚠ Converting several files at once isn't supported yet.

The natural recovery from an error — drop the file again, or drop a different one — walks directly into finding 6. After a successful conversion the state resets correctly and a new drop replaces the old file, so this is specific to the error path.

The escape is ctrl-n, but the warning text points at esc. So the two findings compose into a trap: the error suggests a recovery, the recovery triggers a second error, and that error names the wrong key.

Fix: reset staged state on the error path the way the success path already does.

08

The Resolution step opens on 72 dpi while 150 dpi is labelled "default"

P1shellwrong default · correctness
Resolution
❯ 72 dpi   screen
  150 dpi  default          ← says default, is not selected
  300 dpi  print

Verified on the output, not just on screen: rasterised pages came out 595×842, i.e. 72 dpi. dpiSelect() declares default: '150', but Select initialises to firstEnabled(items) and no call site passes an initial index — so OptionSpec.default is dead for every select in the shell.

It only bites here today because dpi is the one spec whose default is not index 0 (pages, target, rotate, split, extract and compress all happen to have theirs first). The next spec whose default is not first will break silently too. Meanwhile 150 is the documented default everywhere else — --dpi's Commander default, invalidDpi's message, and the choice's own hint — so anyone pressing Enter through a PDF rasterisation gets screen-resolution images and no indication of it.

Fix: make Select honour OptionSpec.default. This is a latent bug in the shared component, not a dpi bug.

src/core/actions/convert.ts:47

09

The result screen never says where the file went

P1both surfacesfeedback

In the shell, a destination typed with a stray leading d — left over from the hint bar's d make default, see finding 12 — made Forge silently create d/nonexistent-root-xyz/out/ three levels deep, write there, and report success: 

✓ done

╭─ PNG ────────╮  ──→  ╭─ JPEG ───────╮
│ big.png      │       │ big.jpg      │
╰──────────────╯       ╰──────────────╯

  83.4 KB → 18 KB · 78.5% smaller

← no folder named anywhere on screen

With the shell defaulting to Desktop and the CLI defaulting to alongside-the-source (finding 23), "where is it?" is the question the result screen exists to answer. The CLI has the same gap for a single file — these two runs print byte-identical success lines: 

$ forge photo.jpg --to png -o out/
✓ photo.jpg → photo.png
$ forge photo.jpg --to png -o deep/nested/dir/
✓ photo.jpg → photo.png     ← identical, wildly different places

Fix: name the directory on the single-file result, on both surfaces. The batch report already does exactly this (Output: batchout/) — copy it.

10

Under NO_COLOR, the page grid has no cursor at all

P1shellaccessibility
0 of 8 selected

╭───╮   ╭───╮   ╭───╮   ╭───╮   ╭───╮   ╭───╮   ╭───╮   ╭───╮
│ 1 │   │ 2 │   │ 3 │   │ 4 │   │ 5 │   │ 6 │   │ 7 │   │ 8 │
╰───╯   ╰───╯   ╰───╯   ╰───╯   ╰───╯   ╰───╯   ╰───╯   ╰───╯

← the cursor is on page 3. Nothing on screen says so.

Focus in PageGrid is a background tint and nothing else — no ❯, no bold, no border change. NO_COLOR=1 correctly strips all colour (zero SGR sequences in the captured frame), which leaves eight identical boxes. Pressing → → space was the only way to find out where the cursor had been.

This contradicts the project's own §13 invariant — "selected rows are marked with ❯ and bold, not colour alone". Select honours it; PageGrid does not. Selection is already handled correctly here (a ✓ in the top border), so the pattern exists in the same component; focus just never got it.

Fix: give focus a symbol or a border change, matching how selection is already drawn.

11

Dropping a folder is refused with a hint recommending folders

P1shellwrong error copy
╭──────────────────────────────────────────────────╮
│ ✕ Not a file                                     │
│ tree is not a file.                              │
│ Point Forge at an image, or at a directory of    │
│ images.                                          │
╰──────────────────────────────────────────────────╯
← tree/ IS a directory of images. That is what was just dropped.

The hint at src/core/errors.ts:79 is written for the CLI, where directories genuinely do work. In the shell it is advice to repeat the exact action that just failed.

Same root cause as findings 3 and 4 — one hint string, two surfaces — but this one is the sharpest, because the user does not just get useless advice, they get advice to do the thing they did.

Fix: surface-aware hints (cause 01). In the shell, either accept the directory or say plainly that folder drops are CLI-only.

12

The hint bar is wrong in the "Type a path…" state

P2shellwrong affordance
─────────────────────────────────────────────
↑↓ choose  │  ↵ next  │  d make default
← the field below is a text input. "d" types a literal d.

The bar keeps the picker's keys after the step has become a free-text field, so three of three advertised keys are wrong at once. This is not hypothetical: it is precisely how the stray leading d in finding 9 got typed, which then silently created a three-level directory tree.

Fix: derive the hint bar from the active input mode rather than the step.

13

The hint bar omits affordances that do exist

P2shelldiscoverability

esc back is missing at the destination step — it works. ↑↓ is missing while the command palette is open — it works. ←→ is missing in the page grid — it works. These are precisely the three steps where a user is most likely to want to change their mind, and in a TUI the hint bar is the only place a key can be learned.

Fix: the keys already exist; only the advertising is missing.

14

The chosen target format disappears after the picker

P2shellorientation

At the Quality step only the source card is on screen. Nothing states what you are converting to until the destination preview reveals it two steps later — so the question "quality for what?" has no answer in view. §10 says a picker "becomes part of the scrollback"; in practice it does not.

Fix: keep the resolved choice visible, either in the mode line or as a second card.

15

/pdf armed before staging is a dead end

P2shelldead end
 current mode: pdf
 → /pdf for page operations
› report.pdf  ⏎
← nothing happens. /pdf has to be retyped after staging.

Everything on screen says the mode is armed — the mode line, the app's own prompt — and then Enter does nothing at all. Silence is the worst possible response here, because there is no way to tell a no-op from a slow operation.

Fix: carry the armed mode through staging, or refuse to arm it before a file exists.

16

Page ops and multi-output conversions get a one-line result

P2shellconsistency
✓ merged 2 files into forge-audit-merged.pdf
✓ converted into 2 files
← no path, no size, no "o open", no "s show in finder"

Single-file conversions get the full result screen with both cards, the size delta and the follow-up keys. Two flows that took more user effort get one line and no way to act on it. Compounds finding 9: here there is not even a filename path to infer from.

Fix: route every completed action through the same result screen.

17

Merge output is named after the containing folder, and cannot be renamed from the CLI

P2CLInaming · parity
$ cd ~/Downloads && forge a.pdf b.pdf --merge
✓ merged 2 files into Downloads-merged.pdf

src/core/output-path.ts:202 names the merge after the shared parent directory, and --output is explicitly refused for page ops — so a CLI user has no way to name a merge result at all. The shell can, via n rename. Same operation, two very different levels of control.

Fix: accept --output for merge, which is the one page op where a name is genuinely needed.

18

The collision error implies nothing was written; one file was

P2CLIaccuracy
✓ 2 converted                      ← which 2?
✕ a.jpg and a.webp would both become a.avif
← "would" is wrong: checkWriteSafety keeps the first claimant,
   so a.avif exists on disk already.

The conditional tense tells the user nothing happened, so the natural next step is to re-run with different flags — on top of a file that is already there. The success line above it does not name which two files succeeded, so there is no way to reconstruct the true state from the output.

Fix: past tense, and name the file that won the collision.

19

forge --help never mentions the config subcommand

P2CLIdiscoverability

config list, config set and config path are fully undiscoverable from help. Since config is what sets the default output directory, this is also the only route to fixing the confusion in finding 23 — and it is invisible.

Fix: one line in --help.

20

config set output accepts anything

P2CLIvalidation
$ forge config set output /nonexistent/nope/deeper
✓ output = /nonexistent/nope/deeper     ← stored without complaint

The bad path is then displayed in the shell banner as the default destination, so it looks authoritative until a conversion fails against it. quality and theme are validated — so the surprise is inconsistency within one subcommand, not a missing convention.

Fix: check the directory exists and is writable at set time, matching the other two keys.

21

There is no /quit or /exit

P2shelldiscoverability
› /quit
⚠ no command matches /quit — try /help
› /help
… (no mention of how to leave)

ctrl-c is in the hint bar, but the command palette is where people look for a named intent — and it answers the most common one with a dead end that forwards to a second dead end. Leaving is the one action every user performs.

Fix: alias /quit and /exit, and name the key in /help.

22

--background is not validated at parse time

P2CLIvalidation
$ forge opaque.jpg --to png --background notacolour
✓ opaque.jpg → opaque.png              ← succeeds, silently

$ forge alpha.png --to jpeg --background notacolour
✕ Conversion failed                       ← same flag, opaque error

The same invalid value produces two different outcomes depending on whether the source happens to carry alpha, and neither of them names the flag. Every other flag in the tool — --quality, --dpi, --rotate, --split, --max-size — validates up front with a message that names the bad value and the valid range.

Fix: parse the colour at argument time, like the others.

23

The shell defaults to Desktop; the CLI writes beside the source

P2both surfacesconsistency

One tool, two answers to "where does my file go?" — and because of finding 9 the shell never tells you which one it used. Either default is defensible on its own; what is not defensible is having both and announcing neither.

Fix: pick one, or keep both and always name the destination on the result (finding 9).

24

The mouse/DSR handshake ignores mouseSupported()

P2shellrendering
^[[22;1R
 ⚒ Forge 0.1.0
← the unconsumed cursor-position reply, printed above the banner under tmux

useMouse gates only on isTTY, so cursor-position queries go out even where the app has already decided mouse support is absent and hidden the clickable result links. The decision exists; this code path just does not consult it. Visible garbage at launch, alongside finding 1's warning.

Fix: gate the handshake on mouseSupported(), not isTTY.

25

Three different error styles in one command

P3CLIconsistency

✕ Invalid arguments          ← full block, symbol + word

$ forge config set quality 999
quality must be between 1 and 100    ← bare line, no symbol

$ forge photo.jpg --to

The middle one breaks §13's own rule that an error carries "a symbol and a word". The third never reaches Forge's error layer at all.

26

P3shellcopy

                ↑ stale                        ↑ destination? unlabelled

Hardcoded at src/shell/intro.ts:111, and stale now that PDF page operations and Word conversion are headline features. On the right, nothing says the path is the destination — which is the same information gap as finding 9, appearing at the other end of the session.

30

Low-information format hints

P3shellcopy
CONVERT TO
❯ PNG    likely bigger       ← cursor starts here
  WEBP   smaller, modern
  AVIF   likely bigger
  TIFF   likely bigger
  BMP    likely bigger

For a JPEG source, four of six targets read "likely bigger" — a hint that repeats cannot discriminate, so the column stops carrying information. And the cursor rests on PNG ("likely bigger") rather than WebP ("smaller, modern"), which is the answer most people dropping a JPEG actually want.

Fix: differentiate the hints, and start the cursor on the recommended target.

What works well

Worth stating plainly, because it is most of the surface. An audit lists what is wrong; this is the part that is right, and several of the fixes above are "do what this part already does".

  • The error taxonomy is unusually good. ✕ Cannot get that small names the smallest size actually achievable; --extract 99 names the page count; unsupported-target lists formats derived from the capability graph rather than a hardcoded list.
  • Compact-width banding is genuinely well done. At 48 columns the file card collapses to one line, choice hints drop, and the hint bar reduces to ↵ send │ / commands. Nothing overflows.
  • Middle-ellipsis truncation handles a 97-character filename cleanly at both 72 and 48 columns.
  • Animation is handled honestly. GIF→WebP keeps all four frames; GIF→PNG converts the first and says so, naming the frame count.
  • The overwrite consent choice — Keep both / Replace / Cancel, with photo (1).webp named in the row — is exactly right.
  • The merge ordering screen — space pick up, s sort, x remove, n rename, with a live output preview and page total.
  • The LibreOffice-absent warning is prominent and gives the exact brew command.
  • Argument validation for --quality, --dpi, --rotate, --split every=N and --max-size is thorough, naming both the bad value and the valid range.
  • Exit codes follow §9 in every case checked: 0 all succeeded, 1 some failed, 2 invalid arguments.
  • Non-TTY handling is correct. forge < /dev/null prints "Forge needs a file and a target format" rather than hanging on a keypress.

Not covered

What this audit did not reach, so the findings above are not mistaken for full coverage.

  • Real Terminal.app. Everything shell-side ran under tmux, which reports no hyperlink or mouse support — finding 24 and the mouseSupported()-gated result links may behave differently there.
  • The LibreOffice-present conversion path — not installed on this machine.
  • Encrypted PDFs and --password-stdin.
  • Batches large enough to exercise concurrency limits.
  • The light theme.
